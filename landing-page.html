🚢 Batalha Naval Multiplayer

⚓

🎯 Sobre o Projeto

Um jogo de batalha naval multiplayer em tempo real, onde o objetivo é afundar todos os barcos do adversário. O projeto foi desenvolvido com arquitetura cliente-servidor, proporcionando uma experiência fluida e interativa.

Como Funciona:

  1. Criar ou entrar em uma sala - Os jogadores podem criar uma nova partida ou juntar-se a uma existente
  2. Posicionar os barcos - Cada jogador define estrategicamente a posição dos seus barcos no tabuleiro
  3. Iniciar a batalha - Sistema de turnos onde os jogadores alternam entre atacar e defender

🚀 Tecnologias Utilizadas

🔹 Backend

  • Node.js – Ambiente de execução JavaScript
  • Express – Framework para criação da API REST
  • Socket.IO – Comunicação em tempo real
  • Cors – Gerenciamento de permissões de acesso

🔹 Frontend

  • React – Biblioteca para construção da interface
  • Vite – Ambiente de desenvolvimento rápido
  • React Router – Navegação entre telas
  • Socket.IO Client – Comunicação em tempo real
  • Tailwind CSS – Framework de estilização

📌 Funcionalidades

Backend

  • Criar e entrar em salas de jogo
  • Gerenciamento de usuários conectados em cada sala
  • Emissão e escuta de eventos via Socket.IO (ataque, resposta, vitória, derrota)
  • API REST para criação/listagem de salas

Frontend

  • Criar uma sala ou entrar em uma já existente
  • Definir a posição dos barcos no tabuleiro
  • Sistema de turnos (atacar e aguardar ataque do oponente)
  • Feedback visual de acertos e erros
  • Indicação de vitória ou derrota ao afundar todos os barcos

🧪 Testes

Casos de Teste:

ID Módulo Caso de Teste Justificativa
T01 Backend - API Criar sala via POST /rooms Essencial para iniciar o fluxo do jogo
T02 Backend - WS Conectar usuário a uma sala (joinRoom) Valida a entrada e sincronização de jogadores
T03 Backend - WS Enviar ataque (attack) Core da mecânica do jogo
T04 Backend - WS Vitória do jogador Valida condição de término do jogo
T05 Frontend - Jogo Posicionar barcos Etapa crítica antes da batalha começar

Resultados dos Testes:

  • T01 (Criar sala): Não foi possível realizar os testes de caixa preta
  • T02 (Conectar usuário): Podem ser conectados até 2 usuários. Equivalência: 2 são válidos; Fronteira: 1 e 3 não são válidos
  • T03 (Enviar ataque): Não foi possível realizar os testes de caixa preta
  • T04 (Vitória): Não foi possível realizar os testes de caixa preta. O jogador só ganha depois de acertar as 10 posições do inimigo
  • T05 (Posicionar barcos): Não foi possível realizar os testes de caixa preta. O jogo não inicia até as 20 posições serem preenchidas

🔧 Versionamento

O projeto segue boas práticas de versionamento utilizando Git e GitHub. A estratégia adotada foi:

  • Branch principal (main): Contém apenas código estável e testado
  • Pull Requests obrigatórios: Toda alteração passa por revisão antes de ser integrada
  • Branches de feature: Cada nova funcionalidade é desenvolvida em uma branch separada
  • Commits descritivos: Mensagens claras que explicam as mudanças realizadas
